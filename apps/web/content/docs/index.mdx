# Overview

cupel is an open source image tool built around one rule: measure before you touch anything. It
works out how much quality a picture actually has left, removes only what it can remove safely,
and records a receipt for every decision so the numbers can be rechecked later.

This documentation describes the repository as it exists today. Anything that has not shipped is
labelled as roadmap, and lives on the [roadmap page](/docs/roadmap).

## Two behaviours that will never be dropped

1. **cupel refuses to re-encode a source with no quality headroom left.** A file that prior
   compression has already spent gets flagged and kept. Refusal is a first class output, not a
   failure state.
2. **cupel never writes anything without an explicit flag.** Every run is read-only by default.
   There is no configuration in which it silently replaces files.

These two constraints predate every feature and outrank all of them. Milestones are designed
around them, not the other way round.

## What ships today

- **`@cupel/core`**: the measurement layer. Five metrics (windowed grayscale SSIM, CIE76 deltaE,
  tiled Laplacian sharpness, 8x8 block boundary energy, radially averaged power spectrum with
  effective resolution estimation) with zero platform dependencies. See [Metrics](/docs/metrics).
- **`@cupel/codecs-node`** and **`@cupel/codecs-wasm`**: two codec adapters behind one `Encoder`
  interface, held to agreement within 1e-6 by a parity test. See
  [Architecture](/docs/architecture).
- **`@cupel/core`'s provenance layer**: what has already been done to a file, read out of its own
  bytes. Estimated original quality, encoder fingerprint, generation count, real versus declared
  resolution, and the headroom verdict that drives refusal.
- **The command line**: `cupel inspect` for one file, `cupel audit` for a folder or a page,
  `cupel write` to apply a plan (dry run unless you pass `--apply`), and `cupel verify` to
  recheck the receipts it wrote.
- **This site**: the landing page runs the real `@cupel/core` code, both at build time for the
  measurement table and in your browser for the demo. The [playground](/playground) runs a full
  sweep on an image you choose without uploading it, and [verify](/verify) rechecks a receipt
  against the files it describes. Neither needs anything installed.

What does not exist yet: page-level budget allocation and source recovery. Both are built and
tested as libraries but nothing calls them yet. The [roadmap](/docs/roadmap) is specific about
this, and about the calibration guesses currently shipping.

## Where the name comes from

A cupel is a small dish used to test what a sample of metal is really worth before anyone decides
what to do with it. Test first, then act. That is the whole reference, and this paragraph is the
only place it lives.
